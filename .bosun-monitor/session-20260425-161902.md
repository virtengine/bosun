## What changed this cycle
### 1. Durable source fix landed — interrupted-run recovery now preserves live claimed runs
Code paths:
- `workflow/workflow-engine.mjs`
- `tests/workflow-engine.test.mjs`

Symptom:
- Starting a second Bosun process while a local simulator run was still alive cleared `.bosun/workflow-runs/_active-runs.json` and made the live run look interrupted even though the original claimant PID was still renewing the task.

Proof:
- live claimant:
  - task `f82209df-e236-4a63-9ce8-67122a1ca96b`
  - PID `50760`
  - command:
    - `node ... bosun/cli.mjs simulate task restart --json --config-dir .bosun --repo-root .`
- live run:
  - `b7a63f0a-5095-48af-9ae1-c9bfefab5d59`
  - `endedAt = null`
  - `run-agent-implement = running` at the time of investigation
- re-entry command:
  - `bosun simulate task f82209df-e236-4a63-9ce8-67122a1ca96b --json --config-dir .bosun --repo-root .`
  - produced no-op run `4cb58f33-b834-49d1-9afb-52216e6113ae`
  - `already claimed, skipping`
- after that second process booted:
  - `.bosun/workflow-runs/_active-runs.json` was rewritten to `[]`
  - the live claim and delegate session still existed

Root cause:
- `workflow-engine._detectInterruptedRuns()` treated persisted `_active-runs.json` entries as interrupted whenever the new process had an empty in-memory `_activeRuns` map.
- It did not check whether the task still had a live local claim PID before pausing the run and clearing the index.

Fix:
- `_detectInterruptedRuns()` now preserves `_active-runs.json` entries when the corresponding task still has a live local claim on the same host.
- Added a focused regression proving locally claimed live task runs are preserved during interrupted-run detection.

Validation:
- `node .\node_modules\vitest\vitest.mjs run tests\workflow-engine.test.mjs -t "keeps active-runs entries for locally claimed live task runs during interrupted-run detection|reconciles interrupted task families into task topology without clobbering a newer completed run"`
- `npm run syntax:check`
