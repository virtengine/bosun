### What changed this cycle
1. **Git push no longer crashes with `ENOBUFS` when pre-push output is large.**
   - Root cause:
     - `workflow/workflow-nodes/definitions.mjs`
     - `execGitArgsSync()` used the Node default sync-process buffer, so a noisy `git push` pre-push hook could overflow and fail with `spawnSync ... ENOBUFS` before Bosun ever saw the real push outcome.
   - Durable fix:
     - `workflow/workflow-nodes/definitions.mjs`
       - default git subprocess `maxBuffer` now uses `16 * 1024 * 1024` unless a caller already sets one.
     - `tests/workflow-task-lifecycle.test.mjs`
       - added regression `captures large pre-push hook output without surfacing ENOBUFS`.
   - Live proof:
     - replay `7ab...` had failed in `push-branch` with `spawnSync ... git.exe ENOBUFS`.
     - replay `724d...` reached and passed `pre-pr-validation`, then failed later in `push-branch` with a normal `Command failed: git push ...` outcome instead of the buffer crash.
