### Root cause
1. **Newer same-task probe runs could clobber `task.latestRunId` even when an older run still owned the live path.**
   - Symptom:
     - the claim-failed probe run `5dac95a9...` became `latestRunId`
     - the real active run remained `12224f60...`
   - Proof:
     - task row pointed to `5dac95a9...`
     - `_active-runs.json` still pointed to `12224f60...`
     - `5dac95a9...` never got past the claim gate
   - Code path:
     - `task/task-store.mjs`
     - `shouldPromoteLatestWorkflowRun()`
     - `linkTaskWorkflowRun()`
   - Why this matters:
     - a no-op same-task probe can hide the real active run in task topology
     - that makes live monitoring and follow-up simulator targeting less reliable
